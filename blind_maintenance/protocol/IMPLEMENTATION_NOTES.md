# Решения реализации и трактовки (фиксируются до confirmatory)

Документ перечисляет места, где спецификация допускала выбор, и сделанный выбор.
Ни один пункт не выбирался по тому, какой результат он даёт: всё решено до
confirmatory-запуска и до просмотра каких-либо итоговых чисел. Неоднозначностей,
которые, по нашей оценке, заметно влияют на результат, не найдено, поэтому основной
запуск не останавливался.

## Случайность
1. Алгоритм: `numpy.random.Generator(PCG64)`. Потоки мира:
   `SeedSequence(world_seed).spawn(6)` в порядке: доступность, износ, сенсорный шум,
   прочий шум, отображение каналов, перестановки q_t.
2. Порядок потребления внутри потока фиксирован кодом `bm/tape.py`. Побитового совпадения
   с исходной реализацией не требуется (§3).
3. Режим износа: равномерное число для переключения берётся только когда dwell≥45; при
   переключении ещё одно целое выбирает один из двух других индексов.
4. h: на каждом шаге берутся и бернуллиевская величина (h≠0 с вероятностью 0.10), и
   нормальная; нормальная используется только при h≠0. На распределение это не влияет.
5. ar и walk обновляются в начале шага и затем используются сенсорами этого шага, то есть
   ar_1 = N(0,0.12²), а не 0. Влияет только на шумовые каналы 3 и 6.

## Сенсоры
6. Размещение: `x[π(i)] = s[π(i)]·raw_i`. Знаки индексируются целевой позицией, буквально
   по тексту §4. Затем центрирование без повторного обрезания.
7. C-scrambled: `x_scr[i] = x[q_t[i]]`. Перестановку выполняет API наблюдений среды, агент
   ленту не получает. Разность берётся с предыдущим уже переставленным вектором.

## Информационная граница
8. Наблюдение агента: t (собственный счётчик шагов, выводимый из своей истории), x (только
   у C/C-scrambled/C-level), R, k, допустимость SERVICE, E, n_o. После действия он получает
   фактическое действие, u (после WORK), обновлённые E и n_o. У fixed, output-only,
   tuned-output, output-trend и Oracle-D x равен None.
9. Oracle-D дополнительно получает преддействующее D текущего шага. Контроллер C получает
   метку y_t = 1[c_t<0.995] (c_t — преддействующая capacity шага t), и только после
   выполненного WORK. Пара обучения: (z_{t−4}, y_t). До действия метка недоступна, после
   SERVICE не выдаётся. Среда проверяет это программно.
10. n_s в очереди C — собственный счётчик SERVICE агента. Он совпадает с n_s среды.

## Учёт
11. N_alive_steps = N_WORK + N_SERVICE, включая шаг смерти. B = G − 0.30·N_alive − 0.12·N_WORK −
    2.25·N_SERVICE.
12. steps_alive = min(death_step, 1000); для выживших 1000. death_step у выживших = NA.
    Флаги survived/died хранятся отдельно.
13. Дополнительная диагностическая метрика: число запросов SERVICE, заменённых на WORK из-за
    недопустимости (`n_denied_service_requests`).
14. Пошаговые логи содержат только шаги, на которых агент был жив и действовал.

## Настройка и анализ
15. Равенство средних G при выборе настроек проверяется точным сравнением float. Порядок
    кандидатов: p по возрастанию; θ по возрастанию; L по возрастанию, затем θ.
16. Выбранные настройки лежат на границах заданных сеток: fixed* dynamic = 5 (минимальный
    p), θ = 0.995 (максимальный). Сетки заданы протоколом и не расширялись.
17. Bootstrap: одна матрица индексов на режим (10 000 × N) от
    `SeedSequence([20260929, mode_code])`, общая для всех стратегий и сравнений режима.
    Благодаря этому сравнения парные. Перцентили 2.5/97.5 считает `numpy.percentile`
    (линейная интерполяция).
18. Контраст dynamic − static: независимые bootstrap-выборки двух режимов, разность
    bootstrap-средних.
19. Темп обслуживания: slow = режим m=0.48, fast = m=1.65. Для fast − slow берётся
    отдельная bootstrap-матрица по подвыборке миров, где оба режима встречались при жизни.
    Её seed: `SeedSequence([20260929, 99, n])`.
20. Wilson-интервал приводится для всех долей выживания. Вырожденный bootstrap помечен.
21. Самостоятельно предложенный дополнительный агент (§7, опционально) не используется.
22. Оператора нет. Master seed генерируется `secrets.randbits(63)` после сохранения и
    публикации манифеста (git push). Это «самостоятельно проведённый holdout, без
    внешнего контроля».
